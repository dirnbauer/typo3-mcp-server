# TYPO3 MCP Server — agent guide

- TYPO3 v14-only MCP extension (`mcp_server`, `hn/typo3-mcp-server`) for editor-friendly, workspace-safe content operations. Non-technical editors edit content through LLMs; tools may change names and parameters when that improves LLM ergonomics — no backwards compatibility promise for tool contracts.
- Read first: `Documentation/Developer/Index.rst`, `Documentation/Architecture/ImplementationOverview.rst`, `Documentation/Architecture/SecurityAudit.rst`, `Documentation/Tools/Index.rst`.
- Commands (PHP 8.4+; `ddev exec` inside the bundled DDEV project): `composer test`, `composer phpstan` (level 8 over all own PHP incl. tests and build scripts, no baseline, no `@phpstan-ignore`), `composer php-cs-fixer:fix`, `composer test:protocol`, `composer test:llm` (needs `OPENROUTER_API_KEY`), `composer docs:check` (host Docker), `Build/runTests.sh -s e2e` (Playwright; `-n` for no Docker).
- Every record-backed tool uses TYPO3 workspaces explicitly and keeps version rows invisible (only live UIDs are exposed). Auto-selecting or creating an MCP workspace is intentional and must keep working in tests; a mixture of live and workspace data is a real scenario.
- In functional MCP tests assert success with `$this->assertFalse($result->isError, json_encode($result->jsonSerialize(), JSON_THROW_ON_ERROR));` (PHPStan level 8 covers the tests: the message must be a string).
- Prefer TYPO3 core APIs and TCA-driven behavior (`DataHandler`, `PageRepository`, FAL, site/language APIs, `TcaSchemaFactory`). Language overlays use `PageRepository`; workspace overlays use the extension's transparency logic (`Documentation/Architecture/LanguageOverlays.rst`). If the instance has no meaningful language support, hide translation parameters and fields — `LanguageService` is the source of truth.
- Security defaults: sensitive headers are never logged, bearer tokens come only from the `Authorization` header, the auth diagnostic stays off by default. File-write tools are restricted to the MCP sandbox in strict mode; physical files are not workspace-versioned. Sandbox, workspace-only writes, the non-workspace-table block and the outbound allowlist relax only when `LocalModeService` reports DDEV / Development context; production pins `localUnsafeMode=off` or `mcpServer.strictSandbox=1`.
- Every new tool declares its subsystems in `Configuration/Capabilities.yaml` (`AbstractTool::execute()` enforces it), calls `CapabilityManifestService::assertUrlAllowed()` before outbound HTTP, and gets a `mcp:<name>` command — a `GenericMcpToolCommand` entry in `Configuration/Services.yaml`; subclass `AbstractMcpToolCommand` only for bespoke options.
- Git: push only to `origin` (github.com/dirnbauer) and `gitlab`; `upstream` (hauptsacheNet) is read-only. Distribution is Composer/Git — no TER, no tailor.
